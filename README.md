# GDHAPP 2.8.1

[Скачать APK](https://github.com/GODIS00/GDHAPP/releases/latest) ·
[Полные исходники 2.8.1](https://github.com/GODIS00/GDHAPP/releases/download/v2.8.1/GDHAPP-2.8.1-source.zip)

В этом репозитории размещены документация и релизы. Полное дерево проекта
с исходниками, библиотеками и скриптами сборки находится в архиве `source.zip`
каждого релиза.

## Обновления через GitHub

Сборка с `-PgithubRepository=OWNER/REPOSITORY` проверяет публичные GitHub Releases
при открытии приложения (не чаще раза в 6 часов). Ручная проверка: Настройки →
О приложении → Проверить обновления. Проверка не блокирует список серверов;
её можно отменить. APK скачивается через браузер, установку подтверждает Android.
Адрес `GODIS00/GDHAPP` уже указан в `gradle.properties`. При пустом значении
`githubRepository` проверка GitHub отключается.

Для следующего релиза увеличьте `versionCode` и `versionName` в `app/build.gradle.kts`.
Скрипт `tools/publish-release.ps1 -Repository OWNER/REPOSITORY` собирает APK для
ARM64 и всех архитектур, проверяет тесты, lint и прежнюю подпись, упаковывает исходники
и считает SHA-256. Ключ подписи хранится только локально, в Git его добавлять нельзя.
Для публикации добавьте `-Publish`; нужен авторизованный GitHub CLI (`gh auth login`).
Скрипт сначала загружает файлы в черновик релиза и публикует его после успешной загрузки.
Репозиторий должен быть публичным, с исходниками и лицензией GPL-3.0.

Первую версию с проверкой обновлений нужно установить вручную поверх старой.
Приложение ищет стабильные теги `vX.Y.Z` и файлы `GDHAPP-X.Y.Z-arm64.apk`
или `GDHAPP-X.Y.Z-universal.apk` в том же репозитории. Токены GitHub в APK не нужны.

## Изменения 2.8.0

Автообновление подписок закрывается кнопкой «Назад» или «Отмена».
Сетевой запрос прерывается, сохранённые серверы остаются доступны. Без сети
обновление при открытии пропускается. Пинг всех серверов вынесен в отдельную
кнопку с прогрессом и остановкой; фильтры и свёрнутые группы не ограничивают проверку.
Свайп вправо запускает пинг, влево — удаление с отменой. Действие выполняется
один раз после отпускания пальца; короткие и отменённые жесты ничего не меняют.
Копирование конфигурации остаётся в меню сервера.

## Изменения 2.7.4

Звук подключения переведён с SoundPool на заранее подготовленный MediaPlayer.
Перед воспроизведением запрашивается кратковременный аудиофокус; после окончания
он освобождается. В настройках оформления добавлено «Прослушать звук» без запуска VPN.
Короткий сигнал доигрывает при открытии системного окна разрешения VPN.
Нулевая громкость, отказ аудиофокуса и ошибка плеера показывают короткое сообщение.
Громкость, вывод звука и сохранённый выбор пользователя не меняются.

## Изменения 2.7.3

Диалог разрешения VPN больше не обрывает короткий звук; при полном уходе

Добавлен исходный `pupue1.mp3` для нажатия «Подключить» в приложении.
Звук заранее загружается, повторное нажатие перезапускает его без наложения.
При выключении настройки или уходе приложения в фон воспроизведение прекращается.
Отключение VPN, автоподключение, шторка и уведомление звук не запускают.
Переключатель «Звук подключения» находится в Оформление → Интерфейс и доступен

Переключатели анимаций, мягкого размытия и тактильного отклика убраны из меню
и поиска. Эффекты включены постоянно; старые сохранённые выключенные значения
исправляются при загрузке и обновлении настроек. Системные ограничения анимации,
вибрации и поддерживаемой версии Android по-прежнему действуют.

## Изменения 2.7.1

Исправлен тактильный отклик: используется стандартный сигнал подтверждения,
а при отказе прошивки — короткий сигнал вибромотора. Настройка действует
на выбор сервера и кнопку подключения; включение переключателя даёт пример
отклика. Системное отключение вибрации учитывается.

KeepAlive сначала выполняет один подготовительный запрос через тот же профиль
и URL. Затем измеряет заданное число запросов по открытому соединению.
При одном замере больше не показывается время первого холодного запроса
с установкой TCP/TLS. Реальное ожидание ответа сервера остаётся в результате.
Если сайт закрывает соединение, новый запрос учитывает повторное подключение.
Default и Disable сохраняют прежнее поведение. Запуск ядра, как и раньше,
не включён в отображаемое время HTTP-запроса.

## Изменения 2.7.0

Сообщение удаления закрывается само и имеет кнопку закрытия; новые сообщения
заменяют старые. Отмена доступна, пока сообщение показано.
В выборе приложений появились иконки, импорт названий/пакетов и экспорт пакетов
в буфер обмена. Импорт дополняет выбор; названия сопоставляются точно, без учёта
регистра. Если название одинаковое у нескольких приложений, выбираются все.
Неустановленные пакеты можно сохранить заранее; неизвестные названия показываются
в окне импорта. Собственный пакет GDHAPP исключён.

Уведомление показывает исходное название сервера без большого флага справа.
Карточка подключения использует Material 3: тональный статус, отдельную кнопку
и компактную строку трафика. Подробности ошибок доступны по нажатию.
Release-сборка оптимизируется R8 с удалением неиспользуемых ресурсов библиотек.
Все четыре архитектуры, оба ядра, мост HEV и базы маршрутизации сохранены.

## Изменения 2.6.0

Вкладка «Проверки» переименована в «Пинг». Поиск серверов убран.
Свайп карточки вправо копирует JSON-конфигурацию, влево удаляет сервер.
Оба действия доступны и через три точки, в списке и сетке.
После удаления доступна отмена. Удаление активного профиля не останавливает
текущий VPN; после отключения используется оставшийся выбранный сервер.
Пустая сетевая подписка остаётся доступной для обновления; пустая локальная
группа удаляется. Следующее обновление получает список заново от провайдера.

Убраны меняющиеся описания способов пинга: переключение не сдвигает карточку.
PNG медленно перемещаются и покачиваются; анимация использует только отрисовку,
останавливается при прокрутке и уходе приложения в фон. Полный цикл — около
2.5 минут. Отключение анимаций в приложении или системе также останавливает фон.
Нижнее меню и панель подключения используют размытие с полупрозрачной подложкой.
Во время прокрутки используется последний сохранённый кадр, без повторной
записи всего экрана и переключения панели на непрозрачный фон.
Кэш содержит только область панели в четверти разрешения, уже с размытием;
он обновляется раз в секунду в покое. При прокрутке рисуется готовое изображение.

## Изменения 2.5.0

Сокращены 75 описаний и подсказок в русском и английском интерфейсе.
Главное меню настроек занимает доступную высоту; на маленьком экране прокручивается.
Разделы открываются отдельными страницами, «О приложении» остаётся последним.
Убраны повторяющиеся вводные заголовки и рекламная подпись на главном экране.
Окно обновления компактное: название подписки, счётчик и прогресс.

Подписки можно обновлять при включённом VPN вручную, при входе и по расписанию.
Ядро продолжает работать со снимком старого профиля; обновление меняет только
сохранённый список. Если сервер удалён, для следующего подключения выбирается
доступный сервер. Панель и плитка показывают текущий профиль до отключения.
Обновление не перезапускает ядро и не обнуляет счётчики. При ошибке старый список
сохраняется. Параллельные обновления сериализованы.

При локальном импорте ключа или JSON без собственного названия группа называется
«Список серверов» (Server list). Имена, заданные провайдером или пользователем,
сохраняются. Для логотипа слева вверху используется отдельный PNG с исходной
прозрачностью, без чёрной подложки.

Исправлен импорт подписок с текстовыми заголовками стран между VLESS-ссылками.
Названия разделов больше не принимаются за Base64. Пробелы, эмодзи и дополнительные
символы # в незакодированных именах серверов не мешают разбору адреса и параметров. Метаданные #profile-title,
#support-url, #announce (включая base64:) и #profile-update-interval сохраняются.
Простые и Base64-списки обрабатываются одинаково; неизвестные URI не скрываются.
Реальный ответ Haven используется только как внешний тестовый файл/явно заданный
URL в опциональной проверке. Подписки по умолчанию в приложении отсутствуют.


В 2.4.0 исправлена форма обводки подключения: сине-фиолетовый градиент
анимируется внутри согласованных скруглённых границ. При отключении анимаций
градиент остаётся статичным. Нижнее меню размывает содержимое только в своём
участке на Android 12+; при прокрутке размытие отключается, фоновые PNG замирают.

В уведомлении заголовок приложения содержит только GDHAPP; время и ядро остаются
в подробностях. В настройках убраны «+» и блок добавления плитки; «VPN для приложений»
перенесён в маршрутизацию, включая результаты поиска.

При входе «Обновлять при открытии» обновляет сетевые подписки с видимым прогрессом,
независимо от периодического расписания. Ошибка
не удаляет сохранённые профили. Автоподключение ждёт окончания этого обновления.

HWID включён по умолчанию: VPN → Автообновление подписок → Идентификация устройства.
При запросе подписки передаются x-hwid, x-device-os, x-ver-os, x-device-model.
Идентификатор приложения получен из Android ID с SHA-256 и сохраняется локально;
IMEI и серийный номер не читаются. Передачу можно отключить. Ошибки лимита устройств
и требования HWID показываются отдельно. Формат соответствует [Remnawave HWID](https://docs.rw/features/hwid-device-limit/).
При переустановке/сбросе данных идентификатор обычно восстанавливается из Android ID;
сброс устройства или смена ключа подписи может его изменить.

Импорт принимает JSON, обычные списки ссылок с комментариями, Base64 и URL-safe
Base64 с переносами строк, а также явные install-ссылки Happ/v2rayNG/v2rayTun.
HTML-страница личного кабинета больше не выдаётся за ошибку Base64.

Системная плитка **GDHAPP** доступна через шторка → Изменить → перетащить GDHAPP
в активную область. Внутри приложения отдельной кнопки добавления больше нет.

Нажатие включает текущий выбранный сервер; повторное отключает соединение,
включая отмену подключения. Плитка показывает сервер и состояние. При первом
включении требуется обычное разрешение Android VPN; отмена не запускает туннель.
При уже выданном разрешении основной интерфейс не открывается. Без выбранного
сервера открывается приложение для импорта/выбора профиля. На защищённом экране
для переключения запрашивается разблокировка. Режим «Только прокси» также поддержан.
Наблюдатели состояния плитки работают только пока шторка видима и не собирают
ежесекундные счётчики трафика.

API и ограничения: [Android Quick Settings tiles](https://developer.android.com/develop/ui/views/quicksettings-tiles).

В 2.3.0 настройки открываются отдельными страницами с возвратом назад;
«О приложении» остаётся последним. Строка «Поиск настроек» ищет функции
по названиям и подсказкам и переводит к нужной карточке. Уменьшены отступы,
высоты строк и заголовки; убран большой демонстрационный блок оформления.
В цветовой схеме доступен свой RGB/HEX-цвет, который сохраняется на устройстве.
Тёмные цвета получают более светлый тон для читаемости в тёмной теме.

Панель активного подключения отстоит от нижнего меню на 8 dp, имеет боковые
отступы 8 dp и скрыта на всех страницах настроек. Появление панели не изменяет
размер списка, оптимизации прокрутки из 2.2.1 сохранены.

Локальный SOCKS5 для приложений по умолчанию выключен; переключатель находится
в VPN → Локальный SOCKS5. Изменение применяется при переподключении.
Обычный Xray VPN использует только native TUN, без SOCKS-входа. Для sing-box
и Xray в режиме совместимости HEV необходим служебный SOCKS-транспорт:
он получает случайный порт и новые случайные логин/пароль на каждом запуске.
Подключения без пароля отклоняются; реквизиты остаются внутри процесса/приватного
кэша приложения и не отображаются как общедоступный локальный прокси.
В режиме «Только прокси» SOCKS5 обязателен, его выключение недоступно.
Проверки профиля (в том числе «Пинг» в уведомлении) при выключенном публичном SOCKS
используют краткоживущую
отдельную сессию и закрывают её после замера, не перезапуская активный VPN.

В 2.2.1 настройки собраны в вертикальные независимо раскрывающиеся разделы:
VPN → Маршрутизация → Оформление → Проверки → О приложении. Последний раздел
содержит сведения о приложении и диагностику; обновление подписок перенесено в VPN.
Состояние раскрытия сохраняется при повороте экрана и переходах между вкладками.

Счётчики трафика подписаны только на индикаторы подключения. Список больше
не получает ежесекундные обновления скорости. Проход размытия ограничен
границами нижней панели 76 dp; при прокрутке серверов он отключён.
Мягкий фон верхней и нижней навигации рисуется градиентами без RenderEffect.
Установочные APK собираются в release без отладочного режима, с прежней подписью.

В 2.2.0 часть PNG наклонена на 7–9°, уведомление использует монохромный щит GD.
Нижняя панель подключения теперь лежит поверх списка: её появление не меняет
высоту списка. На Android 12+ мягкое размытие обрабатывает реальное содержимое
под панелью, сохраняя резкий текст. Карточки отделены от ежесекундных счётчиков,
элементы переиспользуются по типам; фоновые картинки замирают при прокрутке.

Новые настройки:
- **VPN → Режим подключения**: VPN или «Только прокси». Второй режим запускает
  SOCKS5 на `127.0.0.1:10808` (либо заданном порту), без TUN и VPN-разрешения.
  Укажите SOCKS5 в нужных приложениях; их трафик автоматически не перехватывается.
  Для sing-box счётчики в этом режиме недоступны, о чём сообщает уведомление.
- **Маршрутизация**: правила профиля, всё через прокси либо правила клиента.
  Домены и IP/CIDR для обхода и блокировки; блокировка имеет приоритет. В режиме
  правил клиента последующие правила профиля сохранены. Домены включают поддомены;
  CIDR проверяется и после разрешения доменного адреса. Обход LAN и исключения
  приложений применяются Android до правил ядра.
- **Маршрутизация → Фрагментирование**: Xray TLS ClientHello, размер и задержка
  фрагментов. Встроенный transport `finalmask` сохраняет Vision без dialerProxy.
  По умолчанию выключено. sing-box, QUIC и несовместимые цепочки дают явную ошибку.
- **VPN → Автообновление подписок**: интервал провайдера или 1/3/6/12/24 часа.
  Android JobScheduler проверяет сроки примерно раз в 15 минут при наличии сети,
  включая закрытый интерфейс, и может откладывать работу в энергосбережении.
  Локальные профили пропускаются. Активная подписка ждёт отключения; защита
  сохраняется, если подключение началось во время загрузки. Ошибка оставляет
  прежнюю подписку. Фоновые задания не содержат URL или ключей в своих extras.
- **VPN → Поведение**: подключение при открытии и после перезагрузки. Оба
  переключателя изначально выключены. Используется выбранный сервер; для VPN
  заранее нужно разрешение. При загрузке сервис ждёт сеть до минуты. Автозапуск
  после перезагрузки происходит после разблокировки и зависит от ограничений
  Android/производителя. После принудительной остановки может требоваться ручное
  открытие приложения.

Настройки подключения применяются при переподключении. Исходные конфигурации
подписок сохраняются: настройки клиента накладываются на отдельную копию для ядра.

В 2.1.3 добавлены шесть предоставленных PNG-картинок на заднем фоне. Они
полупрозрачны, движутся примерно на 10 dp с циклом около трёх минут и слегка
поворачиваются. «Настройки → Оформление → Форма и движение → Картинки на фоне»
отключает фон. При отключении анимаций картинки неподвижны; при сворачивании
приложения движение приостанавливается. Системное отключение анимаций учитывается.
Исходные PNG сохранены без изменения; для показа декодируются уменьшенные копии.

## Установка

В `artifacts/` находятся APK для arm64 и универсальный APK, архив исходников,
контрольные суммы и результаты проверки. Для большинства современных телефонов
подходит arm64. Универсальная сборка содержит также armv7, x86 и x86_64.

Установите версию 2.8.1 поверх предыдущей GDHAPP, чтобы сохранить свои подписки.
Не удаляйте старое приложение перед обновлением. Идентификатор пакета и debug-ключ
подписи сохранены. Это оптимизированная release-сборка без отладчика. Для
совместимости обновлений сохранён прежний локальный ключ; его нельзя публиковать.

Первый запуск пустой. URL, ключи и демонстрационные серверы в APK не зашиты.
При обновлении удаляется только прежняя группа с внутренним ID `demo-runet`;
пользовательские группы, включая названные RUnet, сохраняются. Сохранённые ранее
адреса Hysteria и другие поля профилей повторно извлекаются из исходного JSON.

## Использование

1. Добавьте собственную подписку по HTTPS, вставьте ссылку/JSON из буфера,
   откройте файл или отсканируйте QR.
2. Выберите сервер. Для проверки работоспособности профиля используйте HTTP GET
   в разделе «Проверки»; URL проверки можно изменить.
3. Нажмите кнопку подключения и разрешите VPN в системном диалоге Android.
4. Параметры туннеля находятся в «Настройки → VPN» и применяются при переподключении.

По умолчанию ядро выбирается автоматически по формату профиля. JSON Xray работает
через Xray, включая XHTTP, REALITY и нативный Hysteria2; JSON sing-box работает
через sing-box. Ссылки Hysteria/TUIC преобразуются в формат sing-box.
Принудительное переключение Xray JSON на sing-box поддерживает базовые транспорты;
профили с XHTTP, особыми правилами Xray или закреплением сертификата требуют Xray.
Вместо потери правил клиент показывает объяснение несовместимости.

## Проверки задержки

| Метод | Что измеряется |
| --- | --- |
| TCP | Установка прямого TCP-соединения с адресом и портом сервера |
| ICMP | Ответ системного ping; доступность зависит от Android и правил сервера |
| HTTP GET | Запрос через отдельную реальную SOCKS-сессию выбранного профиля |
| HTTP HEAD | Запрос HEAD через профиль; сайт может запрещать этот метод |
| TLS | Прямое TLS-рукопожатие с SNI и проверкой сертификата |
| DNS | Время системного разрешения имени сервера; учитывайте кэш |

Настраиваются URL, таймаут, количество повторов и параллелизм; отображается медиана
успешных измерений. Ошибки доступны в сведениях сервера. TCP/ICMP/TLS могут
не отвечать на рабочем UDP- или REALITY-сервере. GET/HEAD проверяют также авторизацию
и передачу данных профиля, а не только открытый порт.

## Импорт и хранение

Поддерживаются полный JSON Xray/sing-box, массив конфигов, обёртка `servers`/`configs`,
Base64 и списки URI `vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria://`,
`hysteria2://`/`hy2://`, `tuic://`. YAML Clash не поддерживается.
Максимум: 2 МиБ на импорт, 500 серверов в группе, 2000 в приложении.
Неизвестные поля полного профиля сохраняются; локальный inbound создаётся клиентом.

Читаются заголовки `profile-title`, `profile-update-interval`, `subscription-userinfo`,
`support-url` и `announce`. Есть обновление URL-подписок и обновление при открытии.
Обновление по интервалу выполняется, пока открыт клиент; отдельного фонового
планировщика и запуска VPN при загрузке устройства пока нет.

Данные сохраняются атомарно в приватном хранилище. Android Backup отключён.
Нечитаемый старый файл сохраняется как `subscriptions-recovery.json` для восстановления.
Пользовательские профили не отправляются разработчику.

## Встроенный транспорт

| Компонент | Версия | Назначение |
| --- | --- | --- |
| AndroidLibXrayLite | v26.10.17 | JNI-обёртка Xray-core |
| sing-box | 1.14.3 | Официальный Android executable, отдельный процесс |
| HEV socks5 tunnel | 2.19.1 | Передача пакетов Android TUN в локальный SOCKS |

Сокеты ядра не попадают обратно в собственный VPN: UID клиента исключён из TUN.
Остальные приложения следуют выбранному режиму. При выключенном IPv6 Android
блокирует IPv6 внутри VPN. Локальный SOCKS слушает только loopback.
Остановка освобождает мост, ядро и файловый дескриптор TUN.

Новый Xray удалил поле `allowInsecure`. Для старого значения `false` оно убирается
без ослабления проверки. При явно заданном `true` клиент получает сертификат
указанного endpoint и закрепляет его SHA-256 на текущую сессию. Если в профиле уже
есть pin, он сохраняется. Проверка QUIC-сертификата со сторонней обфускацией может
быть недоступна; в таком случае используйте корректный сертификат/SNI или нативный
профиль sing-box. Исходный сохранённый JSON эта адаптация не изменяет.

Источники, SHA-256, лицензии и архивы исходников компонентов находятся в `native/`.
См. [native/README.md](native/README.md) и [THIRD_PARTY.md](THIRD_PARTY.md).

## Сборка

Нужны JDK 17/21, Android SDK 35 и Build Tools 36.0.0. Откройте папку проекта
в Android Studio или настройте `JAVA_HOME`, `ANDROID_HOME` и `local.properties`.

```powershell
.\gradlew.bat assembleRelease testDebugUnitTest lintRelease
# APK только для arm64:
.\gradlew.bat assembleRelease -PtargetAbi=arm64-v8a
# Проверить целостность встроенных компонентов:
powershell -NoProfile -File native/fetch-native.ps1
```

APK: `app/build/outputs/apk/release/app-release.apk`. Release не содержит отладчика;
для совместимости обновлений используется прежний локальный ключ подписи.
Gradle получает до 4 ГБ памяти и не более двух workers для упаковки больших ядер.
AGP 8.7.3, Gradle 8.10, Kotlin 2.1.0, Compose BOM 2025.01.00 закреплены в проекте.
По умолчанию собираются четыре архитектуры. Для загрузки отсутствующих native-файлов
из зафиксированных официальных релизов: `native/fetch-native.ps1 -DownloadMissing`.

## Проверка

Unit-тесты проверяют импорт/парсинг, Hysteria endpoint, URI, сохранение конфигов,
маршруты и совместимость TLS. Инструментальные тесты проверяют отсутствие
предзаполненных подписок, миграцию своих данных и реальную передачу HTTP
через оба ядра по VLESS и Hysteria2. Отдельный стенд API 35 проверяет настоящие
пакеты Android TUN, счётчики и остановку сервиса для обоих ядер.

Результаты текущего прогона и контрольные суммы APK находятся в
`artifacts/verification-2.5.0.txt` и `artifacts/SHA256SUMS-2.6.0.txt`.
Пользовательская подписка в окружении разработки отсутствует: её конкретные
серверы здесь не проверялись. Рабочий стенд не добавляет подписки в приложение.

`tools/testing/` содержит локальный HTTP-стенд для TUN-тестов. Запускайте его
только на выделенном эмуляторе; подробности в `tools/testing/README.md`.
